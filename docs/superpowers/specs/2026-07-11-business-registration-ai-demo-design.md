# 工商注册流程 AI 化 Demo 设计

## 1. 目标

构建一个可在本地运行和演示的香港工商注册案件管理系统，跑通“员工建案、客户填写与上传、AI 预审、人工复核、补件、确认单生成、客户确认”的核心闭环。Demo 使用脱敏材料和真实、可替换的 OCR/LLM 服务，不接入真实企业微信、邮箱、TPSI、RPA、支付或签署。

## 2. 成功标准

- 新环境可通过一条命令启动前端、后端、数据库和对象存储。
- 员工可创建案件并获得客户专属访问链接。
- 客户可填写公司、董事和股东信息，并按材料类型上传脱敏文件。
- 系统可执行 OCR、LLM 建议与确定性规则校验，并展示来源和置信度。
- 员工可对照原件复核字段、退回补件或批准案件。
- 系统可生成版本化注册确认单，客户可在线确认。
- 确认后的关键字段变更会使旧确认失效。
- 核心业务规则、API 主流程和浏览器主流程均有自动化测试。

## 3. 范围

### 3.1 客户端

- 通过案件专属链接进入，不依赖企业微信。
- 分步骤填写公司、董事、股东和联系方式。
- 按公司、人员角色和材料类型上传图片或 PDF。
- 查看材料完成度、缺件原因并补交。
- 查看版本化确认单并执行确认。

### 3.2 员工端

- 案件看板与状态筛选。
- 案件详情、材料清单和安全预览。
- 左侧原件、右侧结构化字段的双栏审核工作台。
- 展示 OCR 候选值、置信度、字段来源、规则错误和 AI 建议。
- 支持修改字段、确认候选值、退回补件、复核通过和生成确认单。

### 3.3 自动化能力

- 按案件、人员角色和材料类型归档文件。
- OCR 提取证件与地址证明的候选字段。
- LLM 将材料内容转换为受约束的审核建议。
- 校验材料完整度、地址证明三个月期限、经营范围 30 字限制、手机号格式和持股比例合计 100%。
- 外部服务失败时保留任务状态并允许人工重试。

### 3.4 明确不包含

- 真实企业微信入口、消息回调和机器人答疑。
- 邮箱读取、账号密码解析和官方回执归档。
- TPSI、e-Services Portal 或 RPA 填报。
- 支付、电子签署、生产级多租户、复杂角色权限和运营报表。

## 4. 架构

采用前后端分离的模块化单体：

- 前端：React、TypeScript、Ant Design，包含客户入口和员工工作台。
- 后端：Python FastAPI，按案件、人员、材料、预审、工作流、确认单和审计划分业务模块。
- 数据库：PostgreSQL，保存结构化业务数据、任务状态、版本和审计记录。
- 文件存储：MinIO 私有 Bucket，保存原文件、预览文件和确认单。
- 异步处理：后台任务队列执行 OCR、LLM 和文档生成；业务接口不等待长任务完成。
- 外部服务：OCR 与 LLM 通过统一适配器调用，由环境变量选择提供商；保留模拟适配器用于无凭证开发和稳定测试。
- 本地编排：Docker Compose 提供一键启动和可复现环境。

前后端通过版本化 JSON API 通信。模块在同一后端进程中部署，但禁止跨模块直接操作内部表，由服务接口维护边界，为后续企微、邮箱和官方递交适配器保留扩展点。

## 5. 核心数据与状态

核心实体包括 `cases`、`companies`、`persons`、`shareholders`、`documents`、`extraction_jobs`、`field_candidates`、`field_versions`、`review_findings`、`confirmations` 和 `audit_logs`。

案件状态限定为：

1. 新建
2. 待客户上传
3. AI 预审中
4. 待补件
5. 待人工复核
6. 待客户确认
7. Demo 完成

状态变化必须由显式命令触发并校验前置条件。失败的外部任务不直接改变业务结论；系统记录失败原因，案件进入可重试或人工复核状态。

## 6. 数据流与人工控制

1. 员工创建案件，系统生成不可猜测的客户访问令牌。
2. 客户填写信息并上传文件。原文件写入私有对象存储，数据库保存元数据与存储键。
3. 后端依次执行格式检查、OCR、字段候选生成、确定性规则和 LLM 审核建议。
4. OCR 和 LLM 只能创建候选值或建议，不得覆盖客户原始值或员工已确认值。
5. 低置信度、字段冲突和规则失败进入人工复核，并可追溯到文件、页码和处理任务。
6. 员工确认字段后生成不可变确认单版本。
7. 客户确认后锁定关键字段；关键字段再次变更会使旧确认失效并要求重新确认。

确定性规则优先于 LLM 判断。LLM 不得绕过必填、期限、长度、比例和确认状态校验。

## 7. 界面结构

客户上传端采用分步骤导航，持续展示材料完成度、缺件项和当前处理状态。上传动作绑定案件、人员和材料类型，避免客户自行命名导致归档歧义。

员工审核工作台采用双栏布局：左侧显示受控文件预览与文件列表，右侧显示结构化字段、候选值、置信度、来源、规则结论和操作按钮。高风险字段就地突出，页面底部提供退回补件与复核通过命令。

## 8. 安全与隐私

- Demo 只使用脱敏材料；仓库不得包含真实证件、客户资料或 API 密钥。
- 文件存入私有 Bucket，访问通过后端短时授权接口，不暴露公开 URL。
- 证件号、手机号和邮箱默认脱敏显示，查看原值和下载文件写入审计日志。
- 密钥仅通过 `.env` 注入，仓库只提供 `.env.example`。
- 上传时校验允许的扩展名、MIME、文件头、大小和数量，并预留病毒扫描接口。
- OCR/LLM 日志记录任务编号、提供商和结果状态，不记录证件原文。
- 字段变更、人工复核、客户确认和文件访问均写入追加式审计记录。
- 提供 Demo 数据初始化与清理命令，避免测试材料长期残留。

## 9. 错误处理

- 外部 OCR/LLM 超时、限流或响应格式错误时，将任务标为失败并保存可展示的错误码，允许重试或切换模拟适配器。
- 非法文件在进入对象存储前拒绝，并向客户返回可操作的格式或大小提示。
- 并发修改使用版本号检测，冲突时要求刷新，不静默覆盖已确认字段。
- 确认单生成失败不改变案件状态；成功生成并持久化版本后才允许进入待客户确认。
- 后端错误响应使用统一结构并附请求追踪 ID，日志不包含敏感原文。

## 10. 测试与验收

- 后端单元测试覆盖状态机、材料完整度、日期期限、经营范围长度、手机号、持股合计和确认失效规则。
- 后端集成测试覆盖案件创建、上传、预审任务、人工复核、确认单与客户确认 API 链路。
- 前端组件测试覆盖字段状态、缺件、置信度、风险、加载、空数据和错误状态。
- Playwright 端到端测试使用脱敏样例跑通建案、上传、预审、补件、复核和确认。
- 适配器契约测试确保真实提供商和模拟提供商输出统一结构。
- 故障测试覆盖外部超时、非法文件、低置信度、比例错误和确认后修改关键字段。

## 11. 交付与 Git 策略

按设计基线、工程骨架、案件模块、上传模块、AI 预审、审核工作台、确认单和端到端验收分别提交。每次提交前运行与改动范围对应的格式检查、类型检查和测试。每个大模块完成后检查 GitHub 远端和认证状态；只有已配置目标仓库且验证通过时才推送。
